# Moe_cofe1
веб-приложение для автоматизации кулинарного учета, расчета себестоимости блюд, планирования мероприятий (с разделением на типы) и генерации пакета выходных документов (для клиентов, поваров и бухгалтерии).

## Синхронизация между устройствами

По умолчанию приложение хранит данные только в localStorage браузера и работает локально на одном устройстве.

Для синхронизации между несколькими местами и браузерами подключите Supabase:

1. Создайте проект в Supabase.
2. Скопируйте `.env.example` в `.env` и подставьте значения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. Выполните SQL в SQL editor Supabase:

```sql
create table if not exists app_state (
  id text primary key,
  payload jsonb not null,
  updated_at timestamptz not null default now()
);
```

После этого приложение будет:
- использовать состояние из облака при запуске, если запись уже существует;
- отправлять новые локальные изменения в Supabase и сохранять копию в localStorage;
- проверять изменения с других устройств каждые 3 секунды, а также после восстановления сети или возвращения на вкладку;
- показывать в боковом меню и мобильной панели статус подключения, время последней синхронизации и ошибку с кнопкой повтора.

Если переменные окружения не заданы, приложение продолжает работать в локальном режиме без ошибок.

## Публикация на GitHub Pages

Репозиторий настроен на автоматическую публикацию через GitHub Actions:

1. В репозитории откройте **Settings → Pages** и выберите **GitHub Actions** в качестве источника публикации.
2. Отправьте изменения в ветку `main` или запустите workflow **Deploy to GitHub Pages** вручную на вкладке **Actions**.
3. После успешного workflow ссылка на опубликованный сайт появится в **Settings → Pages** и в окружении `github-pages`.

Workflow проверяет типы, собирает приложение и публикует каталог `dist`. Базовый URL автоматически формируется из имени репозитория для GitHub Pages; локальный `npm run dev` и обычная сборка используют корневой URL.

Для облачной синхронизации добавьте в **Settings → Secrets and variables → Actions** secrets `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Без них приложение будет опубликовано, но сохранит данные только в локальном браузере. Supabase anon/publishable key предназначен для клиентского приложения; доступ к таблице необходимо ограничить политиками Row Level Security и не публиковать service-role key.
